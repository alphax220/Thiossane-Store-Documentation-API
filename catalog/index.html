Catalogue

Jeux publics, catégories, promotions, avis et signalements.

Jeux (API Platform + extensions)

Méthode Endpoint Auth Description
GET /api/games Public* Liste des jeux approuvés (filtre de visibilité)
GET /api/games/{id} Public* Détail d’un jeu approuvé
GET /api/games/{id}/reviews Public Avis du jeu
GET /api/games/{id}/price Public Prix effectif (promo appliquée)
GET /api/games/{id}/ownership JWT Possède-t-on le jeu ?
GET /api/categories Public Liste des catégories
GET /api/categories/{id} Public Détail catégorie

\* Un filtre Doctrine (GameVisibilityExtension) ne renvoie que les jeux approved aux utilisateurs non privilégiés. Les développeurs voient aussi leurs propres jeux via d’autres endpoints (/api/developer/my-games, /api/games?… selon groupes).

Filtres / query params courants

Selon la config API Platform de l’entité Game : recherche, catégorie, plateforme, tri, pagination (page, itemsPerPage).

Champs utiles d’un jeu

  • id, title, slug, description, price, status (draft \| pending \| approved \| rejected \| suspended)
  • coverImage, images de présentation
  • categories, developer / studio
  • playInBrowser, versions (GameVersion : plateforme, démo, fichier)
  • Stats éventuelles (notes moyennes, téléchargements) selon groupes de sérialisation

Avis (reviews)

Méthode Endpoint Auth Description
GET /api/games/{id}/reviews Public Liste des avis d’un jeu
POST /api/reviews/submit JWT Soumettre un avis
GET /api/developer/reviews Dev Avis sur les jeux du développeur
POST/PUT /api/developer/reviews/{id}/reply Dev Répondre à un avis

POST /api/reviews/submit

{
  "game_id": 5,
  "rating": 5,
  "comment": "Excellent jeu !"
}

rating : entier 1–5.

POST/PUT /api/developer/reviews/{id}/reply

{
  "reply": "Merci pour votre retour !"
}

Les avis sont publics en lecture (pas de filtre owner sur la collection). Édition/suppression réservées à l’auteur ou admin (via API Platform + voters).
