Paiements & checkout

État actuel

Paiements temporairement désactivés Dans CheckoutController, $allowedMethods = []. Toute tentative de checkout renvoie 400 : "Unsupported payment method". Les méthodes prévues (quand réactivées) : Wave, Orange Money, YAS.

L’UI front doit afficher « bientôt disponible » et ne pas appeler le checkout pour l’instant, ou gérer explicitement l’erreur 400.

---

Checkout

Méthode Endpoint Auth Description
POST /api/checkout JWT Créer commande + tentative de paiement

POST /api/checkout

Body (quand les méthodes seront réactivées) :

{
  "game_id": 5,
  "method": "Wave",
  "phone": "+221771234567"
}
  • method : une des méthodes autorisées (actuellement aucune).
  • phone : numéro sénégalais, format ^(?:\+221)?[0-9]{9}$.

Rate limiting : par utilisateur (pas par IP). En cas de dépassement → 429 avec header Retry-After.

Réponse typique (si succès) :

{
  "order_id": 18,
  "payment_id": 42,
  "reference": "THS-...",
  "status": "pending",
  "method": "Wave",
  "amount": "2000.00",
  "currency": "XOF",
  "checkout_url": "https://..."
}

Le front redirige vers checkout_url / wave_launch_url selon le prestataire.

Statut de paiement

Méthode Endpoint Auth Description
GET /api/payments/{id}/status JWT Statut par id
GET /api/payments/by-reference/{reference} JWT Statut par référence

Réponse typique

{
  "payment_id": 42,
  "order_id": 18,
  "reference": "THS-...",
  "status": "paid",
  "method": "Wave",
  "amount": "2000.00",
  "currency": "XOF",
  "transaction_ref": "...",
  "paid_at": "2026-09-22T12:00:00+00:00",
  "game_id": 5,
  "game_title": "Mon Jeu",
  "failure_reason": null
}

Statuts (PaymentStatus) : pending \| paid \| failed \| cancelled \| refunded.

Webhooks

Méthode Endpoint Auth Description
POST /api/webhooks/payments/{provider} Public* Callback prestataire

\* Vérifié par signature (PaymentWebhookVerifier).

Ne pas appeler depuis le front. Réservé aux callbacks Wave / OM / YAS.

provider : slug du prestataire (ex. wave, orange-money, yas).
