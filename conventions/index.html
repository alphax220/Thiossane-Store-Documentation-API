Conventions & erreurs

Headers

Content-Type: application/json
Accept: application/json
Authorization: Bearer <access_token>

Pour les uploads (avatar, cover, chunks) : multipart/form-data ou corps binaire selon l’endpoint (ne pas forcer application/json).

Credentials (cookies refresh) : credentials: 'include' en fetch.

---

Codes HTTP

Code Usage typique
200 Succès lecture / action
201 Création
204 Succès sans corps (DELETE)
400 JSON invalide, méthode de paiement non supportée, validation métier simple
401 Non authentifié
403 Pas le droit (rôle / ownership)
404 Ressource absente ou non visible
409 Conflit (email déjà utilisé, etc.)
422 Erreurs de validation API Platform
429 Rate limit (ex. checkout) — respecter Retry-After

---

Corps d’erreur

Format courant des contrôleurs custom :

{
  "message": "Description lisible"
}

API Platform peut renvoyer un document d’erreur plus riche (violations, hydra).

---

Pagination

Collections API Platform :

  • Query : page, itemsPerPage
  • Réponse : liste + éventuellement métadonnées hydra (hydra:totalItems, hydra:view, …) selon le format negotié.

Les listes custom (admin, account) peuvent paginer différemment (voir paramètres du contrôleur ou Util/Pagination).

---

Sérialisation

Groupes typiques : {ressource}:read, {ressource}:write.

Les champs sensibles (mot de passe, tokens, chemins fichiers internes) ne sont jamais dans un groupe :read exposé au client.

Les champs que le client ne doit pas choisir (owner, status de modération, etc.) sont exclus de :write et fixés par des State Processors.

---

Rate limiting

Le checkout est limité par utilisateur. En cas de 429, afficher un message et respecter le header Retry-After.

D’autres limiteurs peuvent exister (login, uploads) selon rate_limiter.yaml.

---

Visibilité des jeux

  • Public / user : uniquement approved (filtre GameVisibilityExtension).
  • Développeur : ses propres jeux via /api/developer/my-games (tous statuts).
  • Admin / modérateur : file /api/admin/games/queue + détail modération.

---

Ownership

Pour les ressources privées listées (orders, payments, favorites, notifications…) :

  • Collection filtrée automatiquement si l’entité implémente ScopedToOwnerInterface.
  • Item : voter OWNER_VIEW / OWNER_EDIT + expressions security sur l’ApiResource.

Les admins passent en général avec is_granted('ROLE_ADMIN') en tête des expressions.

---

Paiements (rappel)

Méthodes désactivées tant que $allowedMethods = [] dans CheckoutController.

Ne pas promettre Wave / OM / YAS dans l’UI tant que le backend ne les réactive pas.

---

Tracking public

Endpoints publics utiles côté marketing / analytics :

  • POST /api/site-visits — tracker une visite
  • POST /api/share/{token}/click — clic lien de partage
  • POST /api/ambassador/{token}/click — clic lien ambassadeur

Pas de JWT requis ; ne pas y envoyer de données personnelles inutiles.
