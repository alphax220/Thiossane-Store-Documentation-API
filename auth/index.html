Authentification

Préfixe principal : /api — pas de JWT pour register/login ; JWT requis pour /api/me et logout.

Vue d’ensemble

Méthode Endpoint Auth Description
POST /api/register Public Inscription utilisateur
POST /api/register/developer Public Inscription développeur (+ profil studio)
POST /api/login Public Connexion → JWT + refresh
POST /api/logout JWT Déconnexion (invalide refresh)
GET /api/me JWT Utilisateur courant
POST / GET /api/token/refresh Cookie ou body Nouveau access token

---

POST /api/register

Créer un compte joueur.

Body :

{
  "email": "joueur@example.com",
  "password": "MotDePasseSecurise1",
  "username": "pseudo"
}

Réponse typique (201) : utilisateur créé + éventuellement tokens selon implémentation.

En cas de conflit email/username → 409 ou 400 avec message.

---

POST /api/register/developer

Inscription développeur : crée le compte et un DeveloperProfile.

Body typique :

{
  "email": "studio@example.com",
  "password": "MotDePasseSecurise1",
  "username": "MonStudio",
  "studio_name": "Mon Studio",
  "website": "https://monstudio.sn"
}

Le rôle résultant est developer.

---

POST /api/login

Body :

{
  "email": "joueur@example.com",
  "password": "MotDePasseSecurise1"
}

Réponse typique :

{
  "token": "<jwt_access>",
  "refresh_token": "<refresh>",
  "user": {
    "id": 1,
    "email": "joueur@example.com",
    "username": "pseudo",
    "roles": ["ROLE_USER"]
  }
}

Le refresh token est aussi posé en cookie HttpOnly (selon config RefreshTokenCookie / gesdinet).

Préférer le cookie pour le front web ; le body refresh_token reste utile pour mobile.

---

POST /api/logout

JWT requis. Invalide le refresh token côté serveur et efface le cookie.

---

GET /api/me

JWT requis. Retourne le profil courant (id, email, username, roles, statut, avatar, etc.).

Pour un profil plus riche (commandes, etc.) préférer GET /api/account.

---

POST /api/token/refresh (aussi GET)

Renouvelle l’access token.

  • Via cookie : envoyer la requête avec credentials, sans body.
  • Via body :
{
  "refresh_token": "<refresh>"
}

Réponse :

{
  "token": "<nouveau_jwt_access>"
}

---

Notes sécurité

  • Access JWT à durée de vie courte ; refresh plus long, stocké en base (RefreshToken).
  • Ne jamais exposer le refresh token en localStorage si le cookie HttpOnly est disponible.
  • Rate limiting possible sur login/register selon config.
