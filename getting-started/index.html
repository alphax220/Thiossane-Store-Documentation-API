Démarrage rapide

Base URL

En développement local typique :

http://localhost:8000

Tous les endpoints sont préfixés par /api.

Headers requis

Content-Type: application/json
Accept: application/json
Authorization: Bearer <access_token>

Le header Authorization est requis pour les endpoints protégés (JWT).

Les endpoints publics (catalogue, register, login, webhooks, deliver signé) n’en ont pas besoin.

Pour le refresh token via cookie : envoyer credentials: 'include' côté fetch/XHR.

Authentification en 3 étapes

  1. POST /api/register ou POST /api/login → reçoit token (access JWT) + éventuellement cookie refresh.
  2. Stocker le token et l’envoyer en Authorization: Bearer … sur les requêtes suivantes.
  3. Quand l’access expire : POST /api/token/refresh (cookie ou body) → nouveau token.

Voir Authentification.

Rôles et headers

Après login, le payload JWT (ou GET /api/me) contient le rôle. Adapter l’UI :

  • user → catalogue, compte, favoris, achats, support
  • developer → + espace dev (jeux, uploads, stats)
  • moderator / admin → + panneaux admin

Format des erreurs

Réponses d’erreur typiques :

{
  "message": "Description lisible de l’erreur"
}

Codes HTTP courants :

Code Signification
400 JSON invalide, validation métier
401 Non authentifié / token invalide
403 Authentifié mais pas le droit
404 Ressource introuvable
409 Conflit (ex. email déjà pris)
422 Erreurs de validation (API Platform)
429 Rate limit (checkout, etc.)

CORS & credentials

Le backend autorise les origines localhost / 127.0.0.1 avec credentials.

En production, le domaine front doit être ajouté dans nelmio_cors.yaml.

Pagination (API Platform)

Les collections API Platform acceptent en général :

  • page (numéro de page)
  • itemsPerPage (taille de page)

Réponse hydra/JSON-LD ou JSON selon la config Accept.
